AT1 Schedule 18 — static text of the XFA template, in document order.

AT1SCH18-dispositions-TRA15156.pdf is a DYNAMIC XFA form: its PDF pages carry
only Adobe's "requires Adobe Reader 8 or higher" placeholder, so pdftotext and
every page renderer return that placeholder and nothing else. The form itself
lives in the /AcroForm /XFA template stream.

Regenerate with:

    python -c "
    import pikepdf, re, html
    pdf = pikepdf.open('AT1SCH18-dispositions-TRA15156.pdf')
    xfa = pdf.Root.AcroForm.XFA
    tpl = next(bytes(xfa[i+1].read_bytes()) for i in range(0, len(xfa), 2)
               if str(xfa[i]) == 'template').decode('utf-8', 'replace')
    for m in re.finditer(r'<text\b[^>]*>(.*?)</text\s*>', tpl, re.S):
        t = ' '.join(html.unescape(re.sub(r'<[^>]+>', '', m.group(1))).split())
        if t: print(t)
    "

Note the tags are written with the closing '>' on the next line, so a regex
that assumes '<text ...>' sits on one line matches nothing.

Order is the template's, which is roughly but not exactly reading order — the
line-number labels cluster separately from their captions, as on any grid form.
Read the numbers off a rendered page in Adobe Reader before trusting an
adjacency here.
